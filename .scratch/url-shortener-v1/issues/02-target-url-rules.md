# 02: Target URL 규칙과 오류 메시지

**What to build:** 방문자가 잘못된 Target URL을 제출하면 Short Link가 만들어지지 않고, 무엇이 잘못됐는지 화면에서 바로 알 수 있다. 입력한 값은 그대로 남아 있어 고쳐서 다시 제출할 수 있다. 검증과 정규화는 Spring에 의존하지 않는 순수 함수(Target URL 규칙)로 만들고, 생성 API가 이 함수를 쓰도록 바꾼다. 규칙은 스펙의 "Target URL 규칙" 항목을 따른다.

**Blocked by:** 01 (워킹 스켈레톤)

**Status:** ready-for-agent

- [x] Target URL 규칙 함수가 앞뒤 공백 제거, scheme과 host 소문자화를 하고, 경로·쿼리·fragment·끝 슬래시는 그대로 둔다.
- [x] 빈 값, URL 형식이 아닌 값, `http`/`https`가 아닌 scheme, host 없음, 2048자 초과, 서비스 자신의 host는 각각 거부 사유와 함께 거부된다. 서비스 host는 설정값으로 주입된다.
- [x] 위 경계 사례를 모두 다루는 단위 테스트가 통과한다(2048자 정확히 허용·2049자 거부 포함).
- [x] 생성 API는 거부된 입력에 `400`과 `ProblemDetail` 본문으로 응답하고, `detail`에 사람이 읽을 사유를 담는다.
- [x] 성공 응답의 `targetUrl`은 정규화된 값이다.
- [x] HTTP 경계 테스트가 거부 사유별 대표 사례 하나씩을 `400`으로 검증한다.
- [x] 메인 페이지는 `400` 응답의 사유를 오류 메시지로 표시하고, 입력값을 지우지 않는다.
- [x] 프론트 페이지 테스트가 오류 메시지 표시와 입력값 유지를 검증한다.
